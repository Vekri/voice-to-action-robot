RAJA — Don't Ask AI. Assign the Task.

Don't just talk to AI. Give AI the ability to act.

I built Raja, a voice-to-action robot. You speak or type in plain English. An agent understands the intent, picks a Python tool, and Raja does the work — then he tells you what he did.

What Raja can do
You talk like a person. He understands. He acts. He answers.

1. Talk like a person
Ask how he is, what he can do, the time, a joke, or any question. He replies out loud — human Q&A, not a menu.

2. Take a data job
• Load retail sales data — opens the file and shows the table
• Visualize — bar, line, area, pie, donut, or table for revenue ($), orders, or customers
• Get insights — reads the numbers and speaks the takeaway

3. Move like a robot
Walk, run, jump, wave, sit, stand, turn, dance. You see the body do the task.

4. Work the way an agent should
One sentence can become a plan: load the retail sales data, then explain it. You see the task list. You hear each step. You watch him finish.

Say it:  load csv  ·  visualize  ·  get insights  ·  dance
Ask it:  hello Raja how are you?  ·  what can you do?

What is this?
This is an AI Agent (agentic AI) — not a chatbot that only generates text.
Raja perceives a request, plans one or more tool calls, then acts: walk, load a CSV, draw a chart, speak the insight.
Generative AI is optional. If an API key is present (OpenAI / Groq / Gemini / Ollama), an LLM can help plan or phrase answers. If not, a local intent parser still routes tools. The product is tool use + action, not text generation.

How it helps
• You talk like a person. No menus, no SQL — say “load csv” or “show orders.”
• One sentence becomes a plan. Raja does the work and says what he found.
• Data becomes a briefing: table, chart, and spoken takeaways.
• You see the action, so you can trust it — motion, lips, tasks, voice.
• The same idea scales: plug in more tools, call them from speech.
• Works without an API key. LLMs are optional.

Architecture
Human  →  Voice (STT) or typed ask
       →  AI Agent (intent + multi-step planner)
       →  Tool calls  (talk, walk, load, visualize, insights, dance, …)
       →  Python tools  (CSV, charts, stats, optional LLM)
       →  Robot body  (pygame pose / lips / motion)
       →  Voice (TTS) + on-screen briefing

Voice → AI Agent → Python Tools → Robot Action

Tools
Talk  ·  load CSV  ·  visualize  ·  insights
Walk  ·  run  ·  jump  ·  wave  ·  sit  ·  stand  ·  turn  ·  dance
Play a short original jam  ·  stop

Stack
Python 3  ·  pygame  ·  SpeechRecognition + PyAudio  ·  pyttsx3 + Windows SAPI  ·  numpy
Optional LLM: OpenAI, Groq, Gemini, or Ollama

Advantages
Natural language in, real action out. Multi-step plans. Visible trust. Local-first. Fast to demo. Cheap to extend.

Disadvantages
This is a desktop simulator, not a physical robot. Local intent can miss messy phrasing. Speech depends on a mic. Not a full BI suite. No long-term memory or live CRM writes. Agentic, but not fully autonomous.

Future
Memory and follow-ups. More tools with confirmations. A stronger planner that asks when unsure. Offline speech. Live data and a briefing export. Optional hardware. A team audit log.

What we add for a real physical robot
Keep the same agent. Swap the pygame body for motors and sensors: Pi or Jetson, wheels, servos, camera, lidar, ROS 2, and a physical stop. Walk becomes navigate. Wave becomes an arm. The leap is actuators and safety — not a new chatbot.
